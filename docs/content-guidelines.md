# Content Guidelines

## 1. Purpose

This document defines the content guidelines for the Manager Library public website.

Its purpose is to ensure that all website content communicates the project's objectives, features, and benefits in a clear, consistent, and professional manner.

**Documentation status:** These guidelines establish the expected content standards for the website. They do not confirm that the content has already been published.

## 2. Target Audience

The website content is intended for people interested in understanding the Manager Library solution, including:

- Library administrators.
- Librarians.
- Educational institutions.
- People interested in library management solutions.

Content should be understandable to visitors without requiring advanced technical knowledge.

## 3. Tone and Writing Style

All website content should follow a consistent communication style.

Recommended characteristics:

- **Clear:** Use simple and direct language.
- **Professional:** Maintain a respectful and informative tone.
- **Concise:** Avoid unnecessarily long paragraphs.
- **Informative:** Explain the purpose and value of each feature.
- **Consistent:** Use the same terminology throughout the website.

Avoid excessive technical terminology, unexplained abbreviations, and unsupported promotional claims.

## 4. Content Organization

Website content should be organized into logical sections.

Each section should:

- Have a descriptive title.
- Present one main topic.
- Include relevant supporting information.
- Use short paragraphs.
- Prioritize important information.
- Avoid repeating content unnecessarily.

Lists may be used when they make information easier to understand.

## 5. Project Description

The project description should explain:

- What Manager Library is.
- What problem it aims to address.
- Who the intended users are.
- What library processes it supports.

Suggested description:

"Manager Library is a library management solution designed to organize book catalogs, member records, loans, returns, and borrowing reports."

This description should remain consistent across the website.

## 6. Feature Descriptions

Each feature should be described using a consistent structure:

1. Feature name.
2. Short explanation.
3. Main purpose.
4. Relevant benefit.

Example:

**Book Catalog Management**

Allows authorized library staff to organize and consult book information, including titles, authors, ISBN numbers, categories, and available copies.

Feature descriptions must reflect the actual project requirements and must not promise functionality outside the defined scope.

## 7. Terminology

The website should use consistent terminology.

| Term | Meaning |
|---|---|
| Manager Library | Name of the library management solution. |
| Administrator | User responsible for administrative operations. |
| Librarian | User responsible for library service operations. |
| Member | Person registered as a library user. |
| Book | A bibliographic record managed by the library. |
| Loan | Record of books borrowed by a member. |
| Return | Process of registering the return of a borrowed book. |
| Overdue Loan | Loan containing an unreturned item past its due date. |
| Category | Predefined classification used to organize books. |

The term "Member" must not be confused with an authenticated application user.

## 8. Accuracy and Scope

All published content must respect the project specifications.

The website must not claim that Manager Library supports functionality that is outside the defined project scope.

The following features should not be presented as available system capabilities:

- Electronic payments.
- Fines and payment processing.
- Book reservations.
- Loan renewals.
- Email or SMS notifications.
- Bulk data imports.
- Multi-branch library management.

Descriptions should distinguish between planned capabilities and implemented functionality.

## 9. Calls to Action

Calls to action should use short, descriptive, and meaningful text.

Examples include:

- Learn More.
- Explore Features.
- Discover Manager Library.
- View Project Information.

Buttons and links must lead to valid destinations. Unavailable destinations should not be published as working links.

## 10. Images and Alternative Text

Images should support the information presented on the website.

Content guidelines include:

- Use relevant and appropriate images.
- Avoid decorative images that create unnecessary visual noise.
- Provide descriptive alternative text for meaningful images.
- Avoid placing essential information only inside images.
- Respect image licenses and usage permissions.

## 11. Accessibility and Readability

Website content should be accessible and easy to read.

Recommended practices:

- Use descriptive headings.
- Maintain logical heading levels.
- Use readable font sizes.
- Write descriptive link text.
- Avoid relying only on color to communicate information.
- Provide alternative text for meaningful images.
- Use simple sentence structures.

## 12. Content Review

Before publishing website content, verify that:

- Information is accurate.
- Spelling and grammar are correct.
- Terminology is consistent.
- Links work correctly.
- Descriptions match the project specifications.
- No unsupported functionality is advertised.
- Personal or confidential information is not exposed.
